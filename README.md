# 学生管理系统 Rust 重构版

控制台版 + 网页版合一：一个 Rust 程序既提供控制台菜单，又内置 HTTP 服务，
网页前端（浏览器）与控制台操作**实时共享同一份数据**。

本仓库是从原版「学生成绩管理系统」v1.4 的 C++ 单文件实现（`sms.cpp`）
逐行为对齐重写的 **Rust 重构版**：功能、接口、数据格式、落盘策略、
线程池与超时行为保持一致，原版源码与 `build-cpp.bat` 保留作对照参考。

## 文件说明

| 文件 | 说明 |
| --- | --- |
| `src/main.rs` | 入口：命令行参数、控制台 UTF-8、组装各模块 |
| `src/store.rs` | 学生数据与 `students.txt` 读写（原子落盘）、控制台表格对齐 |
| `src/http.rs` | HTTP 服务：线程池、路由、JSON 接口 |
| `src/json.rs` | 迷你 JSON 生成/解析（`\uXXXX` 转义、UTF-8 往返） |
| `src/console.rs` | 控制台菜单（0~6）的输入校验与各功能实现 |
| `tests/console_race.rs` | 回归测试：真实进程 + 真实 HTTP，复现"控制台操作时网页端并发改数据" |
| `tests/save_atomicity.rs` | 回归测试：写负载 + 持续读数据文件 + 多轮强杀，验证原子落盘 |
| `Cargo.toml` / `.cargo/config.toml` | 构建配置（静态链接 CRT，免 VC++ 运行库） |
| `index.html` | 网页前端（单页面，无需构建，由 `sms.exe` 直接提供） |
| `students.txt` | 数据文件（UTF-8，每行：`学号,姓名,总分`），每次增删改自动落盘 |
| `build.bat` | 一键编译（cargo build --release，完成后把 `sms.exe` 拷到本目录） |
| `sms.cpp` / `build-cpp.bat` | 原 C++ 版源码与构建脚本（保留参考，不参与默认构建） |

## 编译

```bat
build.bat
```

或手动：

```bat
cargo build --release
copy /y target\release\sms.exe sms.exe
```

依赖：Windows + Rust 工具链（https://rustup.rs）。**零第三方 crate，只用 Rust 标准库**。
编译经 `.cargo/config.toml` 静态链接 C 运行时，产出的 `sms.exe` 不依赖 VC++ 运行库，
Windows 10/11 x64 直接运行（与旧版 `/MT` 静态链接等价）。

## 测试

```bat
cargo test
```

13 个单元测试（JSON 解析、字段校验、数据读写）+ 11 个集成测试。
集成测试会真的启动 `sms.exe`，分两类：

- `console_race.rs`：控制台模式 + HTTP 服务同时跑，一边喂控制台输入，
  一边用 HTTP 请求并发改数据，验证"删除/修改写回前重新按学号查找"这类修复。
- `save_atomicity.rs`：`--server` 模式下并发写负载，同时一个读取器不停读
  `students.txt`，任何一次快照残缺（空文件/半截行/坏 UTF-8/学号重复）即失败；
  再叠加多轮写窗口中强杀进程，验证"先写 `.tmp` 再 rename"的原子落盘。

这些测试都对着真实进程跑，把修复退回到旧写法（例如 `save()` 改回直写原文件），
它们会立刻变红。

## 运行（先运行后端）

```bat
sms.exe
```

启动后：

- 控制台进入菜单（操作提示里的命令行编号 0~6）；
- 同时 HTTP 服务启动，浏览器打开 **http://127.0.0.1:4399/** 即为网页版；
- 服务**只监听 127.0.0.1**，仅本机可访问，同一局域网的其他设备连不上。

其他启动方式：

```bat
sms.exe --server        :: 只跑 HTTP 服务，不进控制台菜单（适合后台运行）
sms.exe --port 9000     :: 换端口，网页访问 http://127.0.0.1:9000/
sms.exe --threads 2     :: HTTP 工作线程数（默认 1，最多 2，范围 1~2）
sms.exe --help          :: 帮助
```

两个端可以同时用：控制台录入的学生，网页刷新即可见，反之亦然。

## 拷贝到新电脑 / 没有 Rust 的电脑

`--server` 模式下想停止：`Ctrl+C`，或在任务管理器结束 `sms.exe`，或执行
`taskkill /F /IM sms.exe`。查看端口占用：`netstat -ano | findstr 4399`。

`双击运行 = 控制台 + 网页服务`。这个模式下**关闭命令行窗口 = 停止网页服务**
（菜单里选 `0` 退出也一样），不会出现“关了窗口网页还能打开”的情况；
如果你遇到过，那是有另一个 `sms.exe` 实例还在后台跑，
用上面的 `taskkill` 结束即可。

拷到新系统也能直接用：程序不依赖 VC++ 运行库，Windows 10/11 x64 即可运行，
把 `sms.exe`、`index.html`、`students.txt` 三个文件一起拷走即可
（`sms.exe` 按自身所在目录找 `index.html` 和 `students.txt`，放哪都对）。

## 控制台功能（0~6）

```
1、录入学生信息    学号/姓名/总分；学号查重，总分限 0~1000000
2、显示学生信息    表格展示（中文按 2 列对齐）与学生人数
3、删除学生信息    按学号删除，需输入 y 确认
4、修改学生信息    按学号修改，直接回车表示该项保持不变
5、查找学生信息    按学号精确匹配或姓名包含关键字模糊查找
6、按总分排序      可选从高到低 / 从低到高，排序结果落盘
0、退出系统        保存数据后退出
```

输入校验：非法命令、非数字成绩、越界成绩都会要求重输；
输入按行读取，任何非法输入都不会死循环，也不影响后续操作。
> 总分范围是 **0~1000000**：原先按语数英三科（各 0~100）记录，
> v1.3.L 起只存一个总分；v1.4 起上限从 1000 放宽到 **1000000**
> （多场考试累加、原始分等场景不必再折算成百分制）。
> 旧版五字段数据文件会在首次运行时自动转成新格式（三科求和）。
>
> 表格里的着色阈值可以在网页上自己改：默认取总分上限的 60% 和 90%
> （即 600000/900000），即**低于及格线红、及格线及以上但优秀线以下黄、
> 优秀线及以上绿**；改法见下面「网页版功能」。阈值只影响网页配色，
> 不改动总分范围和接口校验。

## 网页版功能

表格展示、录入、修改（表单回填）、删除（弹窗确认，可取消）、
查找（学号/姓名关键字）、排序（总分降序/升序/按学号）、刷新，
以及每步操作的 toast 提示和平均分/最高分统计。页面右上角操作提示
2.6 秒自动消失。

**总分三档着色**，阈值可自定义（表单下方的「着色阈值」卡片）：

| 分数 | 颜色 |
| --- | --- |
| 低于及格线 | 红 |
| 及格线及以上、优秀线以下 | 黄 |
| 优秀线及以上 | 绿 |

- 默认及格线 = 总分上限 × 60%（600000），默认优秀线 = 总分上限 × 90%（900000）；
- 输入两条线后点「应用阈值」立即生效，「恢复默认」回到上面两个值；
- 必须是 0~1000000 的整数，且**及格线必须小于优秀线**，否则不应用并提示；
- 阈值只影响网页表格配色，后台 `students.txt` 和接口校验都不变；
- 设置存在浏览器的 localStorage（键 `sms.colorThresholds`），
  换浏览器、清缓存、换电脑都要重新设置。

## 接口（前端与后端对接用）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 网页前端 `index.html` |
| GET | `/api/students` | 学生列表；参数 `sort=total_desc/total_asc/stuno`，`q=关键字` |
| POST | `/api/students` | 录入，JSON：`{"stuno","name","total"}`，`total` 为 0~1000000 的整数 |
| PUT | `/api/students/<学号>` | 修改，字段同录入（`name`/`total` 可只给一部分） |
| DELETE | `/api/students/<学号>` | 删除 |

非法请求会被拒绝并返回中文错误信息：学号重复 409、总分越界/非数字/缺字段 400、
学生不存在 404、方法不支持 405。

示例：

```bat
curl http://127.0.0.1:4399/api/students
curl -X POST http://127.0.0.1:4399/api/students -H "Content-Type: application/json" -d "{\"stuno\":\"2024001\",\"name\":\"张三\",\"total\":263}"
curl -X DELETE http://127.0.0.1:4399/api/students/2024001
```

> 注意：请求体按 `Content-Length` 读取，**不支持 `Transfer-Encoding: chunked`**
> （chunked 方式发送 body 会返回 `400 请求体不是有效的 JSON`）。
> 浏览器和 curl 对已知长度的 body 一律带 `Content-Length`，实际使用不受影响
> （与 C++ 版行为一致）。

## 实现要点

- 纯 Rust 标准库实现，零第三方依赖；控制台主循环与 HTTP 服务线程并发运行，
  学生数据由 `Arc<Mutex<Store>>` 在控制台与 HTTP 之间共享；
- HTTP 服务为「accept 线程 + 固定工作线程池」：连接进 `Mutex<VecDeque>` +
  `Condvar` 队列（上限 64，超出即断开，有意背压），每个连接收发超时 10 秒；
- 数据内存中为 `Vec<Student>`，每次变更立即写入 `students.txt`；
- 落盘为原子替换：先写 `students.txt.tmp`（`BufWriter` + `flush` + `sync_all`），
  再 `rename` 覆盖原文件——任何时刻磁盘上要么是旧的完整文件，要么是新的完整文件；
- `students.txt` 与 `index.html` 按 EXE 所在目录定位（`current_exe()`），
  从任何目录启动都读写同一份数据；
- 内含迷你 JSON 生成/解析（含 `\uXXXX` 转义与 UTF-8 输出），中文经 UTF-8 原样往返；
- 控制台输入在**不持有数据锁**的情况下读取，输入时不会阻塞网页请求；
- 通过 FFI 调用 `SetConsoleOutputCP(65001)` 让控制台正确显示中文；
- 网页端 `fetch` 调用同源接口（都走 http://127.0.0.1:4399），不需要跨域；
  服务端不返回任何 CORS 头，也不监听外网地址，因此网页必须通过上面的地址打开，
  直接双击 `index.html`（file:// 协议）会因跨域被浏览器拦截。

## 更新记录

- **v1.4.1（Rust 重构版修订）**：修复 6 个缺陷，并补上回归测试（`tests/`），
  功能与接口行为不变。
  - **控制台删除/修改不再信旧下标**（本次最重要的修复）：确认删除、改姓名/改总分
    都要等用户输入，而等待期间数据锁是放开的（这是有意设计，输入慢不该挡住网页请求）。
    旧代码把"先查到的 Vec 下标"留到输入之后再用，网页端在这期间删掉前面一条记录，
    下标就指向了别人——轻则删错/改错人，重则 Vec 变短后越界 panic，整个进程退出码 101，
    连正在处理的网页请求一起死。现在写回前重新按学号查找，目标已被网页端删掉就取消并提示。
  - **学号/姓名长度上限改为按字符数**（原来按字节）：40 个汉字的姓名（120 字节）
    以前会被 `valid_field()` 误判成"含非法字符"，现在按界面上"最多 N 个字符"的
    语义正确放行，超长另有单独的"过长"提示。
  - **迷你 JSON 取键**：键名出现在字符串值里时（如 `{"name":"\"stuno\":x","stuno":"REAL"}`）
    旧版遇到第一个同名文本就直接返回 `None`，取不到后面真正的键；现在跳过值里的
    同名文本继续找，也接受键名前是换行/制表符等任意空白。
  - **`\uXXXX` 代理对合并差一**：低代理正好贴在字符串末尾时不合并
    （`\uD83D\uDE00` 即 😀 会变成两个 U+FFFD）。
  - **数据文件不再因一个坏字节被清空**：以前用 `read_to_string()` 读，遇到非法 UTF-8
    字节整份读失败 → 当成空数据 → 第一次保存把全部记录覆盖丢失。现在按原始字节读入
    再宽松转码，坏字节只变成 U+FFFD，记录一条不丢（与 C++ 原版 `getline` 行为一致）。
  - **启动时清掉残留的 `students.txt.tmp`**：上次被强杀在写一半时会留下它。
    不影响数据（从不被读取），但会一直躺在数据文件旁边，现在启动即清。
  - 压测结论同步更新：吞吐、延迟、原子落盘等见 `STRESS_TEST.md`。
- **v1.4.0（Rust 重写版）**：用 Rust 重写全部实现（`src/` 五个模块，零第三方 crate），
  与 C++ v1.4 保持行为对齐：控制台菜单 0~6、HTTP 接口与状态码、
  数据文件格式、原子落盘、线程池（默认 1 上限 2、排队 64）、
  10 秒收发超时、按 EXE 目录定位、`--server/--port/--threads/--help`
  均与旧版一致，`index.html` 未改一行，旧数据文件（含五字段旧格式）直接可用。
  两处顺带的改进：控制台录入时不再持锁（输入期间网页请求不被阻塞）；
  保存文件改用 `BufWriter` 缓冲写（同等数据量下吞吐明显高于逐行写）。
  原 C++ 源码与构建脚本保留为 `sms.cpp` 与 `build-cpp.bat`，便于对照。
- **v1.4**：**总分上限从 1000 放宽到 1000000**。录入、修改、HTTP 接口、
  网页表单的校验范围同步改成 0~1000000；控制台提示语改为由范围常量
  生成（`请输入总分(0~1000000): `），以后调范围只改一处，
  不会再出现文案写死导致前后端不一致。
  顺带修掉 `parseTotal()` 的一个隐患：原先先做 `(int)dv` 取整再比范围，
  提交 `1e300` 这类天文数字会在取整时溢出成未定义行为，现在先比范围再取整。
  数据文件格式、原子落盘、HTTP 线程池与超时行为均不变，旧数据（0~1000）照常可用。
  网页端的表格配色从原来的「绿/红」两档改成**红/黄/绿三档**，且两条阈值线
  可以在页面上自己填（默认取上限的 60% 和 90%，存在浏览器 localStorage），
  不再需要改 `index.html` 里的 `scoreCls()`；控制台没有配色，不受影响。
- **v1.3fix**：修复两个会导致数据损失的问题。
  - **学号录入增加合法性校验**：控制台与网页两端统一对学号执行 `validField()`（非空、≤20 字符、不含逗号/制表符/控制字符）。
    此前学号只查了非空和长度，含逗号的学号能被保存，但落盘后该行字段数改变，**下次启动会被静默丢弃**；
    姓名一直有该校验，学号是漏掉了。现在两端对称，非法学号直接拒绝并提示。
  - **数据文件与前端页面改为按 EXE 所在目录定位**：原按当前工作目录（CWD）打开。
    从其他目录启动（命令行、快捷方式"起始位置"不同、计划任务）时，会读到空数据、
    前端返回 404，并在错误目录里**新建一个空的 students.txt**，造成"数据凭空消失"和数据分裂。
    现在 `students.txt` 与 `index.html` 一律定位到 sms.exe 所在目录；双击运行行为不变。

  HTTP 接口、网页表单与表格全部改成 `学号,姓名,总分` 三项；总分范围 **0~1000**。
  旧版 `学号,姓名,语文,数学,英语` 的数据文件在读入时**自动按三科之和转成总分**并立即转存为新格式，
  控制台会打印提示，不需要手工改文件。落盘的原子性、HTTP 线程池与超时行为不变。
  （初版上限写的是 300，随后按用户要求放宽到 1000。）
- **v1.3**：HTTP 工作线程上限收紧为 **2**，**默认改为 1 个**（v1.2 是默认 4、上限 8）。
  单机自己用：默认一个线程顺序处理连接完全够，页面刷新、增删改都感觉不到差别；
  真要并发时 `--threads 2` 给到两个。排队上限、10 秒收发超时、原子落盘都不变。
- **v1.2**：
  - **落盘改为原子替换**：先写 `students.txt.tmp`，再替换原文件。自己断电、强杀进程、蓝屏都不会再把 `students.txt` 截断成半截文件——要么是旧的完整内容，要么是新的完整内容；替换失败会打印警告，本次修改只留在内存里。
  - **HTTP 连接有超时、不再无限起线程**：固定工作线程从队列取连接处理，排队上限 64，每个连接单次 `recv`/`send` 超时 10 秒。浏览器多开十个标签页反复刷新也只是排队，线程数不会涨；连上却不发数据的客户端 10 秒后被服务端主动断开。（v1.2 初版默认 4 线程、上限 8，v1.3 已改为默认 1、上限 2。）
- **v1.1**：HTTP 服务默认只绑定 `127.0.0.1`（原先绑定 `0.0.0.0`，局域网内可达）；
  删除响应里的 3 行 CORS 头与 `OPTIONS` 预检处理（前端本就同源，无需放行跨域）。
- **v1.0**：首个版本，控制台菜单 + 内置 HTTP 服务 + 网页前端。
