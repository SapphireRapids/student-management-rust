# 测试流程

本文记录本地复现"压测报告"与"原子测试报告"所需的完整操作流程。
环境假设：Windows + Rust 工具链（rustup 安装）+ Node.js（仅压测客户端需要）。

## 1. 构建

```bat
build.bat
:: 或手动
cargo build --release
copy /y target\release\sms.exe sms.exe
```

零第三方 crate；`.cargo/config.toml` 静态链接 C 运行时，产出的 `sms.exe`
不依赖 VC++ 运行库。数据文件/前端页面按 **EXE 所在目录**定位（与当前工作目录无关）。

## 2. 单元测试与集成测试

```bat
cargo test
```

当前 24 个用例：13 单元（JSON、字段校验、数据读写）+ 5 `api_json`
+ 4 `console_race`（控制台/网页并发竞态）+ 2 `save_atomicity`（原子落盘）。
集成测试会真的启动 `sms.exe`、发真实 HTTP 请求。

只跑原子性两个用例：

```bat
cargo test --test save_atomicity
```

## 3. 压测（同机回环）

配方：独立临时目录 → 拷入 `sms.exe` → 生成 500 条种子 `students.txt` →
`--server --port N` 启动 → Node 客户端施压 → 跑完即销毁。

```bat
mkdir C:\temp\sms-stress && cd C\temp\sms-stress
copy ..\..\sms.exe .
:: 生成 500 条种子（学号 2025000001..2025000500）
sms.exe --server --port 4599
:: 另开一个终端跑压测客户端（每请求新建 TCP 连接 + Connection: close）
node stress.js 4599 15000 8
::   ↑ 参数：端口 时长ms 客户端数；混合负载 40% 查列表 / 20% 搜索 /
::     20% 新增 / 10% 改分 / 10% 删除；输出吞吐、p50/p95/p99/max、
::     状态码分布、网络错误数
```

边界项（120 连接突发、空闲连接、半截请求）用裸 socket 客户端打；
强杀用 `taskkill /F /IM sms.exe`；资源核对用
`powershell -NoProfile -Command "Get-Process sms | Select-Object Id,@{N='Threads';E={$_.Threads.Count}},@{N='MemMB';E={[math]::Round($_.WorkingSet64/1MB,2)}}"`。

判定口径：**状态码** 404/409 是配方预期、不算错（200/201 也为预期）；
**网络层真实错误**（ECONNRESET / 超时 / 进程崩溃）才是错误。

## 4. 原子性突变验证（验证测试有牙齿）

目的：证明原子性测试对"退回旧写法"敏感，不是摆设。

1. 备份并临时改 `src/store.rs` 的 `save()`：
   把 `let f = File::create(&tmp)?;` 改成
   `let f = File::create(&self.data_file)?;`（直写原文件，模拟旧写法）。
2. `cargo test --test save_atomicity -- --test-threads=1`
   → 预期两个用例 FAILED（约 7~12 秒内双红）。
3. 恢复 `src/store.rs`，`cargo test` → 预期全绿。

> 注意用 `--test-threads=1` 且给命令加超时；直写原文件会让读取器立刻抓到
> 残缺文件，测试快速失败而非挂住。

## 5. 收尾清理

```bat
taskkill /F /IM sms.exe
:: 删除各临时目录（sms-stress、sms-race、sms-atomic、bare-test 等）
```

检查没有遗孤的 `sms.exe` 进程再离场；`students.txt`、`*.tmp` 都不要带回仓库。
